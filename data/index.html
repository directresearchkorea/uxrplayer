Local LLM Comparison
Qwen · Gemma 로컬 LLM 비교 분석 도입
LLM COMPARE SENTIMENT

기존 형태소 분석(키워드 매칭 + KoELECTRA) 방식의 한계를 보완하기 위해, 로컬 Ollama 기반의 Gemma 2 2B(gemma2:2b)와 Qwen 모델을 활용한 LLM 기반 분류 파이프라인을 구축하고 비교 분석을 수행하였습니다.

Gemma 2 2B 모델은 처리 속도가 빠르고 게이머 슬랭에 대한 인식이 우수하여 로컬 1차 분류기로 최우선순위(Default Model)로 지정되었으며, Qwen 모델은 긴 문맥 이해와 미묘한 반어법 감정 분류에서 강력한 보조 엔진으로 활용됩니다.

KEY FINDINGS

Gemma 2 2B는 경량 모델로서 초당 처리량이 높아 대량 데이터 파이프라인의 1차 분류기로 적합합니다. 특히 갓겜, 망겜, 꿀잼 등 강한 게이머 은어가 포함된 문장에서의 감정 판별 정확도가 높습니다.

Qwen은 한국어 맥락 이해력과 긴 문장 처리에서 안정적이며, 특히 비꼬기·반어법이 포함된 복합 감정 문장(예: "최적화가 너무 잘 돼서 프레임이 10이 나와요 ^^")의 NEGATIVE 판별에서 Gemma 대비 우위를 보입니다.

RAG & Verbatim Pipeline
페르소나 챗봇 RAG 및 대표 Verbatim 추출 프로세스 고도화
RAG VECTOR RE-RANK
1. 프롬프트 방식 vs RAG 방식 구분
프롬프트 방식 (Static Profile Mode) 해당 클러스터의 인구통계학적 요약 정보, 평균 지표(집단 비율, 평균 이탈 위험도 등), 그리고 대표적인 정적 유저 피드백 5건만을 System Prompt에 주입하여 역할극을 수행합니다. 실시간 외부 원문 데이터 조회가 불가능한 독립 연기 모드입니다.
RAG 방식 (Dynamic Grounding Mode) 기획자가 채팅창에 입력한 질문과 실시간 의미 매칭을 수행하여, 커뮤니티에서 기 수집된 실제 유저들의 세부 발언들을 데이터베이스에서 검색해 와 프롬프트 Context로 동적으로 바인딩합니다. 데이터 팩트에 기반한 초정밀 1인칭 대변 모드입니다.
2. RAG 데이터 사전 처리 및 준비 (Pre-processing)

챗봇의 실시간 답변 연산에 지연이 없도록 커뮤니티 데이터 분석 단계에서 다음과 같은 RAG 데이터 전처리를 사전에 일괄 수행합니다.

  • 문장 단위 분할: 크롤러가 수집한 게시글 본문 및 댓글을 KSS(Korean Sentence Splitter)를 이용해 개별 문장 단위로 분할하여 미세 분석 단위를 구축합니다.
  • 밀집 벡터 모델 계산: 분할된 각 문장들을 한국어 전용 문장 임베딩 모델(Sentence Transformer)에 통과시켜 768차원 밀집 벡터(Dense Vector)로 변환하고, 이를 로컬 임베딩 행렬 및 데이터베이스에 사전 계산하여 인덱싱해 둡니다.
  • 메타데이터 매핑: 문장별로 Aspect 카테고리(GRAPHIC, GAMEPLAY 등), 감성 라벨(POSITIVE/NEGATIVE), 감성 신뢰 점수(Confidence Score), 작성한 유저의 고유 세션 및 분류된 클러스터 ID(Active Critics, Casual 등)를 결합하여 DB 구조를 선규정해 둡니다.

3. 페르소나 챗봇 답변 프로세스 (RAG Answering Process)

기획자(PM)가 입력한 질문에 대하여 백엔드(persona_chat_server.py) 서버 측에서 백그라운드로 작동하는 자동 검색-정렬-생성 파이프라인입니다.

  • 1차 후보군 수집 (Top 300): 기획자의 질문 텍스트를 임베딩 벡터로 실시간 계산한 뒤, 전체 문장 벡터 행렬과 코사인 유사도(Cosine Similarity)를 연산하여 가장 높은 유사도를 가진 상위 300개의 후보 문장을 1차로 로드합니다.
  • 2차 필터 및 가중치 계산 (Top 15): 1차 수집된 300개 중, 대화 중인 페르소나 클러스터 ID와 일치하는 저자가 쓴 문장인지 검증하고 스팸/자음 반복 제거를 거쳐 카테고리 매칭 보너스 및 시간 최신성 가중치를 계산해 최우수 15개의 문장으로 후보군을 압축합니다.
  • 최종 Reranking (최종 4개): 15개의 2차 후보 문장을 로컬 PyTorch 기반 교차 인코더(bongsoo/klue-cross-encoder-v1) 모델에 질문과 함께 통과시켜 문맥적 흐름을 재연산하고, 최종적으로 가장 정합성이 높은 상위 4개의 Verbatim(로컬 Ollama 구동 시 3개)을 엄선하여 Prompt Context로 사용합니다.
  • 1인칭 구어체 대변: 이렇게 선정된 근거 피드백을 기반으로 Gemini 2.5 Flash(또는 로컬 gemma2:2b) 모델을 활용하여 1인칭 게이머 말투(해요체, 주로 '~요', '~네요'로 끝나는 말투)로 짧고 명확하게 소감을 답변합니다.

4. 대표 Verbatim 선정 프로세스 (Representative Verbatim Selection Process)

대시보드 메인 화면의 카테고리별 긍정/부정 의견 영역에 정적으로 노출될 대표 의견(Verbatim)을 선별 및 정제하기 위한 주기적 내보내기 알고리즘입니다.

  • 데이터베이스 레벨 1차 필터링: 감성 분석 결과가 명확한 문장(POSITIVE 또는 NEGATIVE)만 대상으로 삼으며, 잡담성 중립 글(NEUTRAL)은 수집하지 않습니다. 또한, 충분한 정보와 묘사를 담고 있도록 글자 수 40자 이상(LENGTH(matched_text) >= 40) 및 모델 판별 신뢰도 75% 이상(confidence_score >= 0.75)의 구절만 DB 상에서 필터링합니다.
  • 신뢰도 및 품질 정렬: 추출 대상 문장들을 ORDER BY confidence_score DESC, LENGTH(matched_text) DESC 기준으로 정렬합니다. 이를 통해 AI 모델이 가장 높은 신뢰도를 주었으면서 풍부한 구체적 설명을 곁들인 유저의 피드백이 항상 최상단에 대표적으로 노출되도록 보장합니다.
  • 노이즈 및 스팸 정규식 클리닝: 정렬 후 루프 분석 단계에서, 특정 한글 초성/모음이 5회 이상 연속으로 나열되어 글의 가치를 저해하는 노이즈 텍스트(예: ㅋㅋㅋㅋㅋ, ㅎㅎㅎㅎㅎ, ㅠㅠㅠㅠㅠ 등)가 감지될 경우 수집 필터에서 자동으로 제외(bypass)합니다.
  • 중복 배제 및 용량 최적화: 날짜, 카테고리, 감성 축별로 동일 문장의 중복 적재를 막는 중복성 검사(deduplication)를 적용하며, 최종 데이터 파일 크기를 경량화하여 프론트엔드 렌더링 성능을 지키기 위해 **날짜-카테고리-감성별 최대 3개**의 고유 Verbatim만 정제하여 최종 아카이빙합니다.

Morphological NLP
파이썬 형태소 분석 기반 카테고리 · 감정 분류 체계 구축
NLP SENTIMENT CATEGORY

붉은사막 커뮤니티 데이터(인벤, 루리웹 등)에 대해 파이썬 기반 형태소 분석을 수행하여 카테고리 및 감정 분류 체계를 확립하였습니다. 사전 기반의 전통적 형태소 분석기(KoNLPy/Mecab) 대신, 게임 커뮤니티 특화 비지도 학습 방식인 soynlp를 핵심 NLP 도구로 채택하였습니다.

soynlp의 LRNounExtractor와 MaxScoreTokenizer를 활용하여 크롤링된 원시 데이터(제목, 본문, 댓글)로부터 동적으로 명사를 추출하고 토크나이저를 학습시키는 구조입니다. 문장 분리에는 KSS(Korean Sentence Splitter)를 사용하여 다문장 게시물을 문장 단위로 분할한 뒤, 각 문장에 대해 Aspect 키워드 매칭 및 감정 판별을 수행합니다.

SENTIMENT ANALYSIS ENGINE (3-TIER)

Tier 1 — 강한 도메인 키워드 오버라이드

강긍정: 갓겜 명작 꿀잼 강추 대만족 인생겜 존잼 → POSITIVE (Confidence 1.0)
강부정: 망겜 똥겜 노잼 쓰레기 최악 환불 비추 접는다 → NEGATIVE (Confidence 1.0)

Tier 2 — Deep Learning (KoELECTRA)

HuggingFace koelectra-base-v3-generalized-sentiment-analysis 모델을 사용한 문맥 기반 감정 분류. Confidence 0.75 미만 시 NEUTRAL로 폴백.

Tier 3 — Lexicon Fallback

오프라인 환경이거나 모델 로드 실패 시, 긍정/부정 사전 단어 카운트 기반 판별.
